# 440 新建会话与页面绑定（2026-09-21，完成）

## 交互

- 点击新建先选择 Agent、目标标签页和可选标题；取消不创建会话。默认展示当前标签页，可按窗口和标签位置区分同名网页。
- 先验证所选标签页的实际 URL / 文档，再创建会话并等待绑定持久化。页面关闭、跳转或连接失败时留在表单，保留输入；绑定保存失败回滚新会话并恢复原会话选择。
- 标题留空继续复用 core 首条消息自动命名；手写标题不被首条消息覆盖。聊天顶栏显示会话标题及 Agent，下面只保留一行可展开页面信息，展开后可定位或重新绑定。
- 历史条目增加页面标题、域名，搜索同时覆盖页面标题与 URL。切换浏览器活动标签不会改变会话目标。
- 目标关闭、URL 变化或连接不可用时保留原页面信息、阻止发送并停止正在运行的会话，草稿仍可编辑。明确重新绑定后继续。
- 侧栏运行期间的同 URL 刷新自动握手新文档；页面曾跳转后再返回仍要求明确绑定，该标记也持久化。恢复时遇到不同文档不会把复用的标签 ID 当成原文档。

## 实现边界

- 运行包增加可选 createSession title 参数，以及无 Chrome / React 依赖的 SessionPageHost 类型。
- 可选 UI 接收 pages 宿主，未提供时嵌入场景只显示 Agent 和标题。Chrome 标签查询、授权、定位和绑定存储留在 extension。
- PageBindings 复用现有存储键，向后兼容已有绑定；串行持久化，防止晚到的旧握手复活已删除会话或覆盖新绑定。
- 同文档 URL 变化更新页面逻辑 documentId，清除旧 DOM 引用；network MAIN 重建该会话的捕获视图，同时保留物理文档的预采集记录。
- 未增加 manifest 权限。Chrome 不返回无权访问标签的 URL/title 时，显示不可访问状态和窗口位置；内置页面不能绑定。
- 实测发现从已有会话新建时重复 React key 导致旧页面条残留，新增失败回归后改为独立的 page key，修复已验证。
