# MCP 集成

本文描述 Web Agent 当前的 MCP（Model Context Protocol）接入边界、生命周期与安全约束。实现由三层
组成：`tools/mcp`（协议客户端、连接管理、失败分类与远端工具适配）、`apps/desktop/src/mcp.rs`
（Tauri 桌面端的 stdio 子进程与 JSON-RPC 会话）、`apps/web/src/mcp`（装配、配置持久化、工具清单
缓存、起进程确认与设置中心状态）。UI 只读取 Einfach atom 并调用命令，不直接访问 registry 或传输层。

MCP 运行时在**应用启动时**装配，不再等用户点开设置弹窗：`apps/web/src/main.tsx` 同步调用
`initializeMcpSettings()` 建立连接器路由与进程级管理器，再以 `void hydrateMcpSettings()` 在后台恢复
配置，不阻塞首屏。装配点是唯一能同时拿到 `toolRegistry` 与管理器的地方，所以 mcp 域工具的依赖注入、
连接目标探针与未连接工具探针都在这里接线。

## 支持范围

| 能力 | Streamable HTTP | stdio |
| --- | --- | --- |
| 运行环境 | 浏览器与 Tauri；浏览器仍受服务端 CORS 约束 | 仅 Tauri |
| 会话持有者 | 官方 TypeScript SDK | Rust/Tauri 后端 |
| 协议版本 | 由 SDK 协商 | 只接受 `2025-11-25` |
| `tools/list` / `tools/call` | 支持 | 支持 |
| `tools/list_changed` | 收到通知后重新对账 | 收到通知后重新对账 |
| 协议 `ping` 保活 | 支持 | 不支持（靠进程退出与管道关闭发现） |
| 退避自动重连 | 支持 | 支持 |
| 按需连接（模型发起） | 支持 | 支持，先过起进程确认 |
| 自动连接 | 支持 | 支持，需命令行已被确认 |
| `resources` / `prompts` | 未支持 | 未支持 |
| 鉴权 | 仅无凭据、无查询参数的基础 URL | 不提供环境变量或凭据字段 |
| 单次响应上限 | 4 MiB（SSE 按单事件计） | 单行 JSON-RPC 16 MiB |

没有凭据保险库：配置层的数据模型**不可表达** `headers` 与进程 `env`，表单也拒绝带查询参数或用户名密码
的 URL，以及形似 token、密钥的启动参数。这类识别只是防误填，不是秘密扫描器；任何连接字段都不应填写
凭据。需要认证的远端 MCP 目前接不上，见「未决决策」。

MCP 本身不等于 tools：协议把 `tools`、`resources`、`prompts` 定义为不同的服务端 primitive，分别在
`initialize` 的 capabilities 中协商。本项目刻意只实现 tools，不能把 resources 或 prompts 伪装成
工具，也不能在没有声明 tools capability 时继续连接。桌面 stdio 客户端只支持 `2025-11-25`：服务端
必须选择这一版本、返回 object 型 `capabilities`、声明 object 型 `capabilities.tools`，并给出非空的
`serverInfo` 名称与版本，任一不符都会断开并卸载工具，不做降级协商。每个 `tools/list` 项都必须提供
根 `type: "object"` 的 `inputSchema`，缺失或根类型不符会被拒绝，不会补成一个看似可调用的空 schema；
本项目尚未实现 MCP Tasks，`execution.taskSupport: "required"` 的工具同样 fail-closed。

## 连接生命周期

**登记与连接是两件事。** `register()` 只把一个已配置服务以 `disconnected` 放进登记表：不建立连接、不发
请求、不起进程；已登记的服务原样返回，不改状态与配置、不重置退避预算、不打断进行中的连接，所以重复
hydrate 不会把一条正在重试或已判永久失败的记录冲回 `disconnected`。这是按需连接的前提：
`connect_mcp_server` 的准入判据就是这张登记表，而记录过去只在真的连过一次之后才存在——不先登记，「已
配置但从未连过」的服务对模型根本不存在。对外看，「只登记从未连过」与「连过之后断开了」不可区分，两者
都是 `disconnected` + 空工具表，含义都是「现在没有连接，要用就得连一次」。

**冷启动。** `hydrate()` 的顺序固定：读服务列表（超过 50 个直接报错，不静默截断）并并行读工具名
缓存 → 把配置里的**全部**服务登记进管理器 → 只对同时满足「用户存过 `autoConnect`」与「这条命令行
已被确认」的服务发起真实连接。`autoConnect` 现在是普通持久化字段，stdio 也不例外，读回来是什么
就是什么，不再把 true 悄悄改写成 false 再回写磁盘；是否真的连接由第三步的运行判据决定，不反过来
篡改用户存过的偏好。冷启动**不**排起进程确认请求：那一刻用户不一定在场，攒出一堆「要执行 X 吗」
只会让人乱点，卡片上点一次「重连」就会问。

### 按需连接：`connect_mcp_server`

模型侧唯一的连接入口。它的输入 schema 与 skill 都是 getter，在调用当刻才现算，所以刚添加的服务
立刻可选、刚删掉的服务立刻消失，无需重新注册工具。

- `serverId` 的 `enum` 等于此刻登记表里的服务 ID。三种情况刻意不写 `enum`：一个服务都没配置时
  （空 enum 是不可满足的 schema，模型只看得出「我错了」）、服务超过 50 个时（截断会让第 51 个真实
  存在的服务被工具自己的 schema 判为非法）、读不出登记表时（不知道有哪些服务就不下断言）；三种
  情况都在参数描述里把事实写清楚。schema 是第一道闸不是最后一道，运行期仍以登记表为准；参数必须
  是字符串，传对象或数组一律拒绝，连接配置因此没有机会从模型侧构造出来。
- 未命中登记表时，形似 URL、路径、命令行、shell 元字符的取值单独识别为 `MCP_CONNECT_TARGET_REJECTED`
  并明确提示这是提示注入，其余为 `MCP_SERVER_NOT_CONFIGURED`；两者都附上可选服务 ID，但**绝不回显**
  被拒的连接目标。服务已连接时直接返回当前清单并标记 `alreadyConnected`，不重连——重连会注销再注册
  该服务的全部工具，打断正在用它的运行。
- 连接超时 180 秒，独立于工具调用的 120 秒（stdio 首次冷启动可能要先下载依赖），返回
  `MCP_CONNECT_TIMEOUT` 且 `retryable: true`，不经失败分类器；连接失败返回 `MCP_CONNECT_FAILED`，
  `retryable` 与 `hint` 完全由失败分类结果决定。
- 成功回执只含 `serverId`、`transport`、`status`、`toolCount` 与最多 50 条工具名和简述，**不回传
  连接配置**（其中的 url / headers / env 可能含凭据）。
- 管理器交给这个工具的能力面被收窄为「按已登记 ID 重连 + 查表」，**不含** `connect(config)`：收
  完整配置的入口一旦出现在工具够得到的类型里，就等于给「模型自己拼一个连接目标」留了后门。

### 状态流转与串行化

```text
disconnected ──connect/reconnect──> connecting/reconnecting ──> connected
      ▲                                  │  └─ 暂时失败：退避重试   │
      └──── disconnect/remove ───────────┴─── 永久失败：error ◀─────┘
```

「注销」关闭当前连接并卸载该服务的全部动态工具但保留配置；「重连」先关闭旧会话，再建立新会话并以
新工具列表对账；「删除」先注销，再删除配置。所有操作按 server ID 串行执行——连接身份的世代检查只有
在「检查与改动之间没有别的操作插进来」时才有意义；任一步骤失败都不能留下一个 UI 显示已断开、
registry 却仍可调用的幽灵工具。每次 stdio 连接还会生成独立的会话令牌，列举、调用、注销与生命周期
事件都携带并校验它，因此旧进程迟到的关闭通知、工具变更通知或取消后的清理请求不会误伤随后建立的新
会话；用过的令牌永久进入 tombstone 集合，不会被第二次接受。子进程自成进程组，关闭时按 grace 轮询
等待，超时则整组强杀，连带 MCP 服务自己拉起的孙子进程。

## 失败分类与自愈

每一次连接、对账或异常关闭的失败都被分成两类：**暂时**（`reconnecting`，值得重试）与**永久**（`error`，
重试不会自愈，需要人工改配置、环境或服务端实现）。分类只服从一条规则：**永久结论只能来自对端不参与
撰写的信号**——桌面 stdio 桥的结构化失败 kind、HTTP 响应状态码、本包自己抛出的确定字符串；远端
JSON-RPC 错误文本、HTTP 响应体、SDK 措辞至多只能选择原因标签，一律落到暂时失败。这个不对称是刻意的：
把暂时失败判成永久会停掉全部重试并需要人工介入，而对端只要在一次普通 500 里回一句「invalid token」
或「exceeded 5 tools」就能随意触发它；反过来把永久失败判成暂时，只是多花掉有限几次退避尝试，预算
用尽后同一个失败照样浮出来。

- 桌面桥的 kind 经不可枚举属性跨界传递，绝不进 UI 文本。只有「OS 拒绝启动配置的命令」与「对端破坏
  了 MCP 契约」两种判永久；子进程已经起来之后的宿主侧装配失败仍可重试；内联了对端原文的 kind 被
  标记为「对端撰写」，直接跳过全部消息匹配规则。
- HTTP 状态码由传输层观测而非服务端撰写：401/403 判永久（认证失败），其余 4xx（除 408、429）判
  永久（配置无效），其余判暂时；状态码旁边的散文是响应体，不参与判定。没有 401/403 佐证时，
  「unauthorized」之类措辞只能把原因标签定为认证失败，不能终结重试。

暂时失败装填退避重连：1s → 2s → 4s → 8s → 16s → 30s，共 6 次、约 61 秒后停手（不加抖动），然后落成
带最后一次原因的永久失败。次数上限是必需项而不是调参——正因为重试有预算，分类器才敢把「看起来像认证
失败但没有状态码佐证」的错误判成暂时。手动连接、重连、注销、删除与一次连接成功都会取消退避并把预算
还回去。

**保活探活。** 长时间没有流量的连接可能早就死了（对端重启、NAT 超时、代理掐断），而传输层未必给得出
关闭事件。已服役的连接因此被周期性探活：**用 MCP 协议自带的 `ping`**，30 秒探一次、单次 10 秒超时、
连续 2 次不通判死（最坏 80 秒发现）。不拿 `listTools` 当心跳——它的代价随工具数线性增长，且拿到清单后
几乎必然顺手对账，连「工具名冲突」这种与连接死活无关的失败都会被当成断线。不实现 `ping` 的传输就不
起表，绝不退化成用 `listTools` 顶替：目前只有 Streamable HTTP 实现了它，stdio 不需要——子进程退出、
管道关闭是 OS 级的确定信号，会直接走关闭事件。判死后**不自己重连**，而是当成一次「传输层没来得及告诉
我们的意外关闭」交回连接状态机：串行队列、世代检查、失败分类与退避预算全部沿用同一条路。

## 工具适配与对账

远端工具以稳定命名 `mcp__<server-id>__<remote-tool-name>` 注册进本地 registry：显示名可以变化，
`server-id` 隔离同名服务，远端工具名用于在 `tools/call` 中还原调用，超过 64 字符或含不安全字符时退化
为带稳定哈希的短名。`inputSchema` 经形状校验与防御性克隆后作为懒加载 schema，限制 128,000 字符、
32 层、4,000 个节点，避免不可信服务用极深或超大定义拖垮递归校验器。远端文本、图片、音频、资源链接或
结构化内容作为规范化结果返回，不在适配层猜测业务语义；单次模型可见结果限制 1,000,000 字符、64 层、
20,000 个节点，传输私有的 `_meta` 不进模型上下文。真实错误返回 `ok: false`，已经成功执行但输出非法或
超限时返回固定的 `ok: true` 丢弃标记，提醒模型不要仅为取回输出而重试可能非幂等的工具。单次工具调用
硬超时 120 秒。

每次连接、重连或收到 `tools/list_changed` 后都执行集合对账：新增工具注册；同名工具覆盖为最新
schema/描述；内容等价的同名工具复用原注册及版本，忽略对象键顺序和仅影响 UI 的标题变化；已移除工具
注销；连接关闭时注销该服务命名空间下的全部工具。全部校验（`tools/list` 最多 100 页 / 1000 个工具、
空名、schema 形状、命名冲突）都在任何注册/注销之前完成，抛出即表示 registry 未被改动。
`tools/list_changed` 采用 single-flight：突发通知最多保留一次正在执行的刷新和一次 dirty 刷新；注销、
重连、删除或异常关闭会取消旧刷新，迟到结果不能重新挂回工具。真正发生 schema、描述或执行约束变化时才
签发新注册版本，旧版本的待确认或在途调用会被原子拒绝，要求模型重新加载 schema。工具调用沿用现有
`AbortSignal`，非取消异常转换为普通 `ToolResult` 错误。

## 单次运行内的工具集

registry 是进程级共享且随时可变的，而 MCP 的通知与断线会立刻增删工具。为此每个 run 在开始时冻结一份
工具清单：**清单在 run 内固定**（中途注销的不消失、中途注册的不混入，否则注入的 manifest 文本会与
模型的发现面自相矛盾，并让 provider 的前缀缓存整段失效）；**成员只增不减**（中途新注册的工具可被点名
加载和执行，只是不进清单；注销过的成员保留为「已退役」）；**注册版本不冻结**（真正执行的是 registry
里活着的实例，冻住旧版本会让版本校验 fail-closed，把工具在本 run 剩余时间里变成永久不可用）。由此
产生两条给模型的结构化回执，语气刻意不同：

- `tool_provider_disconnected`——连过、本轮掉了，不可重试。回执明说「这不是你的调用出错，它还在清单里
  只是为了让清单在一次运行内保持稳定」，要求改用其它手段或如实告知用户。它在工具闸门、执行器与确认
  恢复三处投递，闸门那一处排在所有其它检查之前，避免先装一份注销前的 schema 把模型骗到下一轮。
- `tool_provider_not_connected`——压根还没连上，连上就能用。触发条件是这个名字对本 run 完全陌生，而它
  出现在某个**未连接**服务的「上次已知」清单里。回执带上服务 ID、上次探测时刻，以及一条指向
  `connect_mcp_server` 的后续调用建议；取不到可靠时间时写「时间未知」，绝不编造新鲜度。服务已经连上
  时这条探针必须闭嘴，否则会把模型推进「连接 → 还是没有 → 再连接」的死循环。

## 工具清单缓存

按需连接之后，未连接服务的工具不在 registry 里。模型必须先知道「我要的能力在哪个服务上」才谈得上
决定要不要连，这条线索来自一份**上次已知**的工具清单缓存。

**来源**有两处：添加或导入服务时探测一次（顺带当场验证配置，把「工具数超限」「工具名冲突」这类硬失败
从对话中途提前到表单上），以及此后每次连接成功、或对账后工具集真的变化时刷新。没勾自动连接的服务在
探测完成后立即断开——留着连接就等于绕过按需分层，模型会直接看见并调用这些工具。断开、连接失败、退避
重连**一律不动缓存**：「现在没连着」绝不是「这个服务没有工具」。

**落点**是桌面端 `~/.webAgent/config.json` 的 `mcp.toolNameCache` 段（目录 0700、文件 0600、原子写，
按顶层键合并，不影响同段其它键），浏览器与测试退回 localStorage 或内存。**只存工具名与短描述，绝不存
`inputSchema`**：schema 属于按需加载那一层且要求工具已注册，缓存它会诱使模型直接调用未连接的工具，
破坏惰性加载的分层。**上限**（这份数据最终整体进模型上下文）：单服务 200 条工具、单条描述 160 字符、
单条名字 200 字符、整份缓存序列化后 20,000 字符；超总量时只截断正在写入的那一条，从其工具列表尾部
逐个丢，绝不收缩其它服务已缓存的数据，截断后仍保留探测到的真实总数。

**呈现分两层**，因为两层的代价差一个数量级。工具名进 `connect_mcp_server` 的 **manifest 描述**（每次
请求都发，≤1,200 字符、≤12 个服务 × 12 个名字，带 UTC 日期与真实总数）——名字就是路由键，这条信息如果
只躺在 guide 里就会死锁：模型不知道那边有东西，就不会去加载说明，于是永远不知道那边有东西。完整清单
（工具名 + 短描述 + 精确到秒的 UTC 时间戳 + 拿不到清单的服务及原因）进 **guide**（≤6,000 字符、≤50 个
服务 × 40 条），只在模型主动请求工具说明时给一次，那正是它已经决定「我要连点什么」的时刻。超预算时
先从条目最多的服务尾部丢工具名，让预算被所有服务分摊，只有每个服务都只剩一个名字仍超限时才整条丢弃
服务，并把丢掉的条数写进文案：被丢掉的服务必须留下痕迹，否则模型会把「没列出来」读成「没有这个能力」。

只有管理器说**未连接**的服务才展开历史清单，且遍历以登记表为准，缓存里残留的、早已被删掉的服务不会
因此复活。「探测失败」「尚未探测」「探测到空清单」三种都进「暂无已知清单」桶，措辞明确写成「不等于
没有工具」。缓存读出口没接线时 manifest 与 guide 一个字都不写：宁可让模型少看到一段提示，也不能凭空
断言某个服务有或没有某些工具。所有文案都写明「上次已知」并带时间戳，否则会被当成当前事实。

## 配置与持久化

配置是可持久化的数据，连接是进程内的瞬时状态。HTTP 配置保存服务名与 URL；stdio 配置保存服务名、命令、
参数、工作目录与起进程确认记录；两者都带 `autoConnect`。连接状态、错误、远端工具定义和活动 client
不持久化。服务列表当前写在浏览器 `localStorage`（键 `web-agent.mcp-servers.v1`），桌面端也走这里，写
配置文件的通道已经实现但尚未接线，见「未决决策」；持久化不可用时退化为内存存储，设置中心会明确提示
刷新或关闭页面后配置丢失。最多保存 50 个服务，超限与 ID 重复都明确报错；读盘时按白名单重写，非法条目
整条丢弃、未知字段不落地、`autoConnect` 非布尔值按 false 处理。

设置中心支持常见的 `mcpServers` 格式，可以一次导入一个或多个服务，也支持带 `name` 的单服务对象：

```json
{ "mcpServers": { "playwright": { "command": "npx", "args": ["@playwright/mcp@latest"] } } }
```

- JSON 文本按 UTF-8 计算最多 256 KiB；解析前会手写扫描并拒绝重复键——`JSON.parse` 会静默保留最后一个
  同名键，攻击者可借此藏一个服务或替换掉安全字段。批量导入是原子的：整批先完成解析、字段校验、名称
  冲突与数量校验，再一次持久化，任一项失败或持久化失败时均不添加任何服务。
- stdio 服务仅接受 `command`、`args`、`cwd`、`type`、`transport`；HTTP 服务仅接受 `url`、`type`、
  `transport`；单服务格式另外要求 `name`。`command` 自动推断为 stdio，`url` 自动推断为 Streamable
  HTTP，可选的 `type` / `transport` 只能显式声明与推断相同的传输方式。严格拒绝 `env`、`headers`、
  `token`、`autoConnect` 及其他未支持字段，不静默丢弃；导入项一律以 `autoConnect: false` 落盘。
- 导入落盘后会在后台**逐个探测**（不并发，避免一次打满远端与本地连接），把工具清单收进缓存并在状态行
  上报进度与汇总；探测结论不影响导入成功与否，失败的配置照样保留。未确认命令行的 stdio 导入项只排一条
  确认请求、不进探测循环——让后台顺序循环停下来等人点确认，会把排在后面的 HTTP 探测一起卡住。浏览器
  可以保存 stdio 配置但无法启动它，且浏览器与桌面端配置不会自动同步。

## 安全边界

MCP 服务是应用之外的信任域。**起进程确认（用户路径）**：桌面端 stdio 服务在本机第一次执行某条命令行
之前，必须由用户看着「将执行 `<command> <args>`」点确认。确认**绑命令行，不绑服务**——记录的是
command、args、cwd 的规范化 JSON 元组指纹，任何一项被改过（将来的编辑界面，或者用户手改配置）都会与
指纹对不上，确认自动作废、下次再问一次。如果只记一个布尔，改完命令之后旧确认照样成立，下次冷启动就会
无人过问地执行新命令；指纹让「改了命令 = 确认作废」成为数据模型自带的性质。指纹比对只有一处（读盘时
只校验记录形状）。确认点覆盖添加、导入、重连、打开自动连接四个入口，并在真正调用连接之前再兜一次底；
点确认后先落盘再执行，落盘那一轮里指纹又变了或服务已被删则不执行。

**模型发起连接的风险分级。** `connect_mcp_server` 不进危险工具静态集合，而是按目标服务分级：stdio →
需要确认，且确认卡片的说明里带上将要执行的命令行（这个工具的参数只有 `serverId`，不写出来用户看不到
真正发生什么）；Streamable HTTP → 只发一次网络请求，放行。四种「答不上来」——参数不是字符串或为空、
探针没接线、服务 ID 未登记、探针本身抛错——一律按需要确认处理，绝不因为查不到而静默放行一次进程启动。
探针只回答「会不会起本机进程」和「命令行是什么」，不回传 url / headers / env。

**「一律允许」不记忆连接类工具。** 会话级的「一律允许」按工具名记忆、不看参数，所以凡是风险由参数决定
的工具都没有资格进这份记忆。被排除的有两类：全部 `mcp__*`（实现在外部服务里，重连后同名工具可能换一套
行为），以及 `connect_mcp_server`（同一个工具名，`serverId` 指向 HTTP 只是一次网络请求，指向 stdio 就是
在本机拉起子进程；对一个服务点一次「一律允许」若能记住工具名，本会话内连接任意已配置服务都不再确认）。
判据只有一处，但在命令层、writer 与 reader 三处各守一层，即使记忆集合被污染也永不认账。

其余约束：

- 所有 `mcp__*` 调用都标记为危险操作且不做参数级细分，也不可显式授权给子 Agent，必须留在父级执行边界
  内。会话处于 Auto 模式时危险操作直接执行（含 MCP 工具调用与 stdio 连接），只有被判为 critical 或
  显式要求确认的调用才仍然暂停。
- 第三方 `description`、schema 和工具名只用于模型提示，不作为授权依据；注销与连接异常会立即卸载
  工具，避免继续调用失效或来源已变化的能力。
- Streamable HTTP 在 SDK 解析前限制响应体：非 SSE 整体、SSE 单事件各最多 4 MiB，声明长度与实际分块
  流量都会校验。子进程 stderr 被持续消费（防止管道写满阻塞子进程）但只留在 Rust 侧的尾缓冲里，不混入
  JSON-RPC stdout，也不序列化进 Tauri 返回值、前端错误或模型上下文；stdio 请求有超时，退出时执行会话
  清理与子进程终止。

后续如果引入服务级信任、只读工具或跨会话的「始终允许」，必须基于可审计的服务身份、能力快照和细粒度
权限，而不是匹配名称或自然语言描述。

## 未决决策

以下事项已经识别但尚未决策，落地前不应开工。

**删除服务时是否清掉它的工具清单缓存。** 删除一个服务后，它的缓存条目会留在配置里。影响有限：
manifest 按管理器登记表遍历，不会把已删服务列给模型；模型真去连也会被明确拒绝，不构成死循环；缓存
总量上限也让它不会无限增长。属于陈旧数据残留而非功能缺陷，但「删了还留着」在隐私上不干净。

**schema 校验失败时是否回显实际取值。** 全仓通用的 enum 失配错误会带上模型传来的原始字符串。给
`connect_mcp_server` 加了 `serverId` 的 enum 之后，一次注入式调用被 schema 挡下时，那个地址会原样
出现在工具结果里——execute 路径上刻意维持的「不回显攻击者地址」在 schema 路径上不成立。严重度有限：
该字符串本来就在模型自己那条 tool call 的参数里，回显不引入新信息。但这是全仓所有工具共用的错误
格式，改动面在 `agent-core`，且要在「可诊断性」与「不复述不可信输入」之间取舍。

**凭据支持（当前的实际阻塞项）。** 配置层主动丢弃 `headers` 与 `env`，参数校验还把疑似 token 的
启动参数判为错误，因此**任何需要认证的 MCP 服务现在都接不上**。安装即探测把这件事从「以后再说」
变成「立刻可见」：这类服务在安装时必然探测失败、缓存为空，于是 manifest 没有清单可给，按需模式对
它们完全失效。要不要做、走静态 token 还是 OAuth，未定；做 OAuth 的话连接状态机需要预留一个「待
授权」状态。

**要不要保留显式的连接工具。** 既然安装时已拿到全部工具清单，理论上可以取消 `connect_mcp_server`：
把缓存里的工具作为占位直接注册进 registry，模型照常调 `mcp__<服务>__<工具>`，运行时发现未连接就先
透明连上再执行。取舍是明确的——透明模式省一轮往返但费上下文（20 个服务 × 20 个工具 = 400 条摘要进
每次请求），显式模式省上下文但多一轮，且起进程的确认能落在一次语义明确的调用上，而不是突然插进一次
业务调用里。当前按显式设计，理由是本仓库已经为了上下文经济做了惰性 schema 加载，透明模式与那个取向
相悖；改成透明模式意味着按需连接这一整支重写。

**异步长任务。** 适配层拒绝声明 `taskSupport: "required"` 的工具，且每次调用硬超时 120 秒。要支持
跑得久的工具就得改动 run 的暂停/恢复模型，工作量大于本次重设计的总和。

**MCP 配置本体是否迁出 localStorage。** 工具清单缓存已经进了 `~/.webAgent/config.json`，而服务列表
仍在 `web-agent.mcp-servers.v1`，形成两处存储。写配置文件的通道已经实现
（`apps/web/src/mcp/tauriMcpConfigStorage.ts` 的 `createDesktopMcpConfigStorage`），但装配点没有接线，
所以桌面端的服务配置——包括起进程确认记录——目前仍落在浏览器存储里。是否一并迁移、存量怎么迁，未定。

另有一项经评估后**决定不做**：在首个 run 组装工具清单之前等待首次连接 settle。当初立项是为了消除
「第一条消息看不到 MCP 工具」，但既然每个已配置服务在安装时就有缓存清单，模型在任何时刻都能看到全部
工具，没有东西需要等；剩下的唯一价值是省一次无谓调用（常驻服务还在连接途中时模型可能白调一次连接
工具），代价却是给 run 生命周期加一条阻塞路径。
