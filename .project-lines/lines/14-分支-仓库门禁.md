# 线：仓库门禁家族

一句话：把「违反了也不报错」的设计红线写成 node 脚本，让它在 CI 里以非零退出码红掉。

类型：分支线——挂在 `.github/workflows/ci.yml:10` 那唯一一条 `web` job（CI 时）与
`package.json` 的 `check:*` 脚本（本地手跑时）。

## 入口（一个实例从哪开始）

- `.github/workflows/ci.yml:22`、`:24`、`:26`、`:39`、`:51`——五条门禁在同一条 job 里的五个步骤，
  夹在 `pnpm install`（`:21`）与 `pnpm test` / `pnpm build` / `pnpm -r build`（`:28`、`:29`、`:38`）之间。
  整条 job 共 9 个 run 步骤，其中 5 步是门禁。
- `package.json` 的 `check:boundaries` / `check:state` / `check:dist` / `check:packed` 四条别名；
  `check-docs` **没有**别名，CI 与文档都直接写 `node scripts/check-docs.js`。
- `.github/workflows/release-npm.yml:152-167` 重跑其中四条（docs / boundaries / state / dist），
  理由写在 `:150`：tag 可以指向任何 commit，而 ci.yml 只在 `pull_request` 上触发。

## 数据怎么走（一条门禁的一次运行）

1. 声明判据 → 脚本顶部的常量表。`check-boundaries.js:23-92`（4 条 core 规则 + 能力包规则 + 厂商名
   红线 + 公开面白名单 + 两张豁免表）、`check-docs.js:20-27`（忽略目录、两条链接正则、旧路径正则、
   两项豁免）、`state-invariants/atomDispositionTable.js:16-114`（六张归宿表）。
2. 枚举扫描面 → 各自的文件遍历。`check-boundaries.js:186-199` 只走 `<group>/<pkg>/src`；
   `state-invariants/sourceFiles.js:13-25` 走 `packages` / `tools` / `apps` 整棵树；
   `check-docs.js:30-42` 从仓库根递归所有 `.md`（不看 git 索引，未跟踪文件同样被扫）。
3. 判定 → 逐行正则或结构化抽取，结果分流进 `errors` 与 `observations` 两个数组
   （`check-boundaries.js:207-212`、`check-state-invariants.js:41-43`）。豁免命中降级成
   observation 而不是消失，`check-boundaries.js:136`、`:163` 各把豁免理由原样打进输出。
4. 汇总与退出 → `errors.length > 0` 即 `process.exitCode = 1`
   （`check-docs.js:117-121`、`check-boundaries.js:218-222`、`check-state-invariants.js:49-53`）。
   `check-packed-server.js:252-255` 换了形态：自定义 `GateFailure` 类，其它异常打完整 stack。
5. 结果去哪 → CI 步骤红。绿的时候各自打印一行带**计数**的结论：docs 112 个 md、boundaries
   831 个非测试 TS/TSX × 7 条规则、state 1453 个文件 × 5 条规则、dist 17 个包 26 个公开入口、
   packed 五条判据加分步耗时（`check-packed-server.js:240-241`）。

后两条门禁的「数据」不是源码而是**产物**：`check-dist.js:172-185` 走
`npm pack → 解包 → 改写 workspace 依赖 → repack → 临时工程 npm install → 逐条 import + tsc`；
`scripts/packed-server/consumerInstall.js:127-144` 走 `pnpm pack 发布闭包 → 仓库外 npm install`，
再由 `packed-server/serverProcess.js` 起进程、`check-packed-server.js:225-237` 打真实 HTTP 请求。

## 每部分负责什么 / 状态归谁 / 谁能调谁

| 部分 | 职责 | 持有的状态 | 谁可以调它 | 不许做 |
|---|---|---|---|---|
| `check-docs.js` | Markdown 相对链接必须存在；禁止写出迁移前的旧源码目录字面量（`:26` 的 `legacySourcePathPattern`） | 忽略目录集与 2 项文档豁免（`:8-23`） | ci.yml、release-npm.yml、人手 | 无 `--root`，只能扫自己所在的仓库 |
| `check-boundaries.js` | 包**之间**的边界：import 方向、core 厂商名、core 公开面白名单九条 | 4+1 条规则 + 厂商名豁免 1 项 + subpath 豁免 2 项（`:59-92`） | 同上 + `pnpm check:boundaries` | 不解析行内注释，跨行 import 只认 `} from '…'` 收尾行（`:225-226` 自陈） |
| `check-state-invariants.js` | 只做装配：按序跑 5 条规则、汇总、打印（`:10-11` 自陈） | 规则顺序（`:27-33`）、`--root`（`:23-24`） | ci.yml、`pnpm check:state` | 不放判据、不放表 |
| `state-invariants/*.js` | 一条规则一个模块 + 两个抽取模块 + 一张表 | 见下 | 只被入口 import | 两条规则各写一遍「什么算 derived」（`derivedPurity.js:13-15` 明确导出给规则 4 复用） |
| `check-dist.js` | 可发布包**装得上**：dist 在、26 个公开 ESM 入口 import 得动、`.d.ts` 在 NodeNext 下可用、两条负向实验 | 无表，靠 `files` 含 `dist` + 有 `build` 脚本筛出 17 个包（`:46`） | ci.yml、release-npm.yml、`pnpm check:dist` | 不跑那个二进制 |
| `check-packed-server.js` | 打包产物**跑起来真能干活**：五条判据（`:14-19`） | 服务标识、库文件名、SQLite 魔数（`:39-45`） | ci.yml、`pnpm check:packed` | 不重抄宿主的库路径算法，只认文件名（`:146`） |
| `packed-server/{consumerInstall,serverProcess}.js` | 前者只管「产出真实用户拿到的东西并装到仓库外」，后者只管进程起停与残留复查 | `RELEASE_FILTER`（与 release-npm.yml 逐字相同，`consumerInstall.js:30`） | 只被 `check-packed-server.js` import | 互相越界（两个文件头都写了分工） |

`state-invariants/` 的 9 个模块：5 个规则模块（`derivedPurity` / `writeChokepoint` /
`slotJournalShape` / `atomDisposition` / `agentStoreBinding`）、2 个抽取模块（`slotSource` 认
`slot(...)` 调用，`sessionAtomSource` 认 `atom(...)` 声明，`slotSource.js:3-4` 写明为什么分成两个）、
1 张表（`atomDispositionTable.js`，`:3-5` 写明「判定与账分开，改 atom 的人只需要读表」）、
1 个共享文件口径（`sourceFiles.js`）。

## 形状

- 成员 5 个（`git ls-files scripts` 里的 `check-*.js` 入口）。
- **精确主形状 4/5** `{scripts/check-<名>.js 入口 + package.json 的 check:* 别名 + ci.yml 一个步骤}`。
  不合的是 `check-docs.js`：只有前后两项，没有 package.json 别名。
- **超集 5/5** `{入口脚本 + ci.yml 一个步骤}`——这是真正的必需部分。
- 可选部分，按落实数排：
  - `--root <dir>` 注入（可对临时 fixture 目录跑）：**2/5**——`check-boundaries.js:8-9`、
    `check-state-invariants.js:23-24`。docs / dist / packed 都写死自身仓库根。
  - fixture 自测（`*.test.js`，随 `pnpm test` 一起跑）：**1/5**——只有
    `check-boundaries.test.js`，14 条用例，正反两面都测（命中失败 / 豁免只报观察项 /
    换个消费方仍失败 / 测试文件不进扫描面）。`pnpm exec vitest list scripts/` 确认它在全量套件里。
  - 判据拆成子模块：**2/5**——state（9 个）与 packed（2 个）。
  - 文件头写设计理由：**3/5**——boundaries 31 行注释 / 256 行、packed 28/256、state 入口 11/64；
    **docs 与 dist 各 0 行**。dist 的设计理由整段写在 `ci.yml:30-50` 的 YAML 注释里，不在脚本里。
- 两条通道是所有门禁共有的：`errors` 让 CI 红，`observations` 打印但放行；每条豁免必须带
  `reason` 字段并原样打印（`check-boundaries.js:136`、`writeChokepoint.js:135-137`）。

## 样板

- `scripts/check-state-invariants.js` + `scripts/state-invariants/`——**判据最多、拆得最开的那个**。
  入口 64 行只做装配；5 条规则各住一个模块并各自导出 `{ summary, run }`
  （`derivedPurity.js:50-53` 是最小实例）；表与理由住模块里，报错信息指向**表**而不是判定文件
  （`atomDisposition.js:36-37` 明确写了为什么）。要加第 6 条规则，照这个形状加一个文件 + 在
  `check-state-invariants.js:27-33` 的数组里加一行即可。
- `scripts/check-packed-server.js` + `scripts/packed-server/`——**最近且干净**（2026-08-19 出生）。
  三个文件三件事：验什么 / 产物怎么来 / 进程怎么起停，每个文件头第一句就是「这个文件只负责……」。
  判据编号进错误文案（`:49-51` 的 `fail(criterion, detail)`），红的时候直接告诉你是第几条。

## 标准之外

### 另一类（同在 `scripts/`，不同机制）

判据是三条：**判的是谁**、**跑在哪一环**、**动不动东西**。门禁判仓库源码或它的产物、跑在 CI、只读。

- `scripts/model-preview-relay*.ts`（5 个文件）——运行期组件，浏览器 dev 下的本地模型中继，
  由 Vite 装配（`CLAUDE.md:94-96`）。它是被门禁保护的对象，不是门禁。
- `scripts/public-model-credential-guard.ts`——**最像门禁的那个「另一类」**：它确实会让构建失败，
  但它不是脚本，是 `vite.config.ts:12`、`:219` 在配置阶段调的一个函数，没有 CI 步骤、没有退出码，
  也不遍历仓库——只看传进来的 15 行环境变量表（`:1-5`）。它属于「模型凭证与传输」那条线。
- `scripts/fix-dts-specifiers.mjs`——构建后处理，**写产物**（改 `dist/**/*.d.ts` 的相对说明符），
  被 17 个包的 `build` 脚本调用。它制造 `check-dist.js` 要验的那份东西。
- `scripts/subagent-*.js`（14 个文件）——运行期**数据**治理，判的是 `.webAgent-archive/` 里的用户
  数据而不是仓库源码，且默认 dry-run、`--write` 才落盘（`subagent-index-compact.js:37`、
  `subagent-archive-retention.js:58`、`subagent-skill-governance.js:44-46`）。全部不在 CI 里。
  它们的 6 个 `*.test.js` 会随 `pnpm test` 跑，但那是普通单测，不是门禁自测。
- `scripts/cache-investigation/`——一次性调查报告，读桌面 trace SQLite 出验收指标
  （`report.js:2-4`），口径挂在一份 followups 文档上。

### 漂移 / 遗留（少、晚、不合形状——是「别模仿」不是「删」）

- `scripts/check-docs.js`——三项可选部分一项没有：没 package.json 别名、没 `--root`、没 fixture
  测试、0 行注释。它是**最早**的门禁（`6067088`，2026-08-03，比第二条早 10 天），形状还没长出来。
- `scripts/check-dist.js`——0 行注释、没 `--root`、没测试，而它是判据最绕的一个（解包→改写
  workspace 依赖→repack→装→两条负向实验）。设计理由整段在 `ci.yml:30-50`，跟着 CI 走而不是跟着
  脚本走：单独看这个文件读不出它为什么存在。
- `state-invariants/sourceFiles.js:13-25` 的扫描面**不排除 `dist/`**。实测本机 1453 个被扫文件里
  610 个是 `packages/*/dist/**/*.d.ts` 与 `tools/*/dist/**/*.d.ts`（跟踪的非测试 TS/TSX 只有 843 个）。
  CI 里恰好无症状——`pnpm -r build`（`ci.yml:38`）排在 check-state（`ci.yml:27`）**之后**，那时
  dist 还不存在；本地跑过一次构建之后就有了。对照组是 `check-boundaries.js:193`，它只走
  `<group>/<pkg>/src`。当前不误判（`.d.ts` 里既没有 `atom((get` 也没有 `useSetAtom(`），
  但计数不可复现，且下一条按行文本扫描的规则会直接扫到产物上。
- `.github/workflows/release-npm.yml:169-251` 把 packed smoke **内联重写了一遍**（pack → 仓库外
  npm install → 起服务 → 读横幅端口 → health + 根路径），而不是调
  `node scripts/check-packed-server.js`。两处判据不等价：内联版没有判据 2（无 token 401）、
  没有判据 4（真的落盘的 SQL）、没有判据 5（残留进程）。它比 `check-packed-server.js`
  早出生（`3e5c8bb` 2026-08-19 早于 `d9b87eb` 同日）。

### 其实合规（看着像漂移，核过不是）

- `scripts/check-boundaries.js` 233 行单文件、表内联——它是**唯一**带 fixture 测试的门禁，
  14 条用例把每条规则的命中/放行/豁免三态都钉住了，判据没有靠拆文件也说得清。
- `writeChokepoint.js:62` 与 `:68` 两张表**都是空的**，`slotJournalShape.js:59` 的 `snapshotOnly`
  与 `atomDispositionTable.js:114` 的 `knownLoss` 也是空的。四处都写了「空不等于不需要这张表」
  的理由（`atomDispositionTable.js:112-113` 最明确）。空表是设计，不是残留。

### 待确认（≤5）

1. **新门禁默认要不要 `--root` + fixture 测试**（`scripts/check-boundaries.test.js:38-40`）：
   A 是必需的，只是 docs/dist/packed 三条欠着，下一条门禁必须带上；
   B 只有「判据是逐行正则、容易写错」的那类才配自测，dist/packed 这种「真跑产物」的门禁
   自身就是端到端实验，再套一层 fixture 是空转。
2. **`state-invariants/sourceFiles.js:13` 要不要排除 `dist/`**：A 是漏，扫描面该与
   `check-boundaries.js:193` 对齐到 `<pkg>/src`；B 是有意——本地跑时顺带扫一眼产物没坏处，
   CI 里因为顺序天然扫不到。答案决定下一条按行扫描的规则敢不敢直接复用这份文件清单。
3. **`.github/workflows/release-npm.yml:169` 的内联 smoke 要不要换成调
   `scripts/check-packed-server.js`**：A 应该换，两处判据不等价就是「验的是 A、发的是 B」；
   B 刻意保持内联，发布流水线不依赖仓库脚本。答案决定 packed 门禁加第 6 条判据时要不要同步改
   YAML。
4. **`check-docs` 要不要补 `check:docs` 别名**（`package.json` 现有 4 条 `check:*`）：
   A 补，五条门禁一个调用形状；B 不补，它不吃参数、CI 直调就够，`CLAUDE.md:23` 写的本来就是
   `node scripts/check-docs.js`。答案决定「加一条门禁」的清单里 package.json 那行是必需还是可选。
