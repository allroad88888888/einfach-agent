# 线：运行时插件家族
一句话：把「跨轮、跨工具才成立」的横切行为做成注册到 `LoopHooks` 七个槽上的插件，主循环只在到点时调那个复合槽。
类型：分支线——挂在主线的 `packages/agent-core/src/runtime/toolLoopBootstrap.ts:46`（运行时：每 run 激活一次插件集）与 `packages/agent-core/src/runtime/core/plugins/defaultPlugins.ts:7`（编辑/配置时：内建插件的登记表）

## 入口（一个实例从哪开始；引 file:line）
- 契约面：`packages/agent-core/src/runtime/core/loopHooks.ts:164-192` —— `LoopHooks` **7 个槽**：`onRunStart` / `transformContext` / `prepareRequest` / `beforeToolCall` / `afterToolCall` / `onTurnEnd` / `shouldStop`。
- 注册面：`packages/agent-core/src/runtime/core/pluginApi.ts:34-51` —— `PluginApi` 给插件 4 件事：`hook` / `registerTool` / `subscribe` / `observeRun`，外加只读的 `commands`。
- 插件本体：`packages/agent-core/src/runtime/core/pluginApi.ts:55` —— `AgentPlugin = (api: PluginApi) => void | (() => void)`，装配期跑一次、注册意向、可返回 dispose。
- 内建登记表：`packages/agent-core/src/runtime/core/plugins/defaultPlugins.ts:7-11` —— **当前 3 个**：migration / loopGuard / finishReason。
- 外部插件契约（另一套形状）：`packages/agent-core/src/runtime/core/pluginContracts.ts:86-102` 的 `definePlugin` + `PublicPluginDefinition{install?,activate?}`，公开入口 `packages/agent-core/src/plugin.ts:4-19`。

## 数据怎么走（逐步；每步引 file:line）
1. 声明 → 逻辑本体写成可独立单测的具名函数，插件函数只做一行注册。三个内建插件都是这个形状：`migrationPlugin.ts:41`（`applyMigration`）+ `:58-61`（注册 `onRunStart`）；`finishReasonPlugin.ts:59`（`applyFinishReason`）+ `:106-108`（注册 `onTurnEnd`）；`loopGuardPlugin.ts:108`（`createLoopGuardDetector`）+ `:182-185`（注册 `onTurnEnd`）。
2. 注册 → 两条路。**内建**：写进 `defaultPlugins.ts:7-11` 的数组，`pluginHost.ts:185-187` 在每次 `activateRun` 时**延迟 import** 并拼在实例插件前面。**实例/动态**：`createCore({ plugins })`（`createCore.ts:50` → `coreInstance.ts:203`）走构造期安装；`pluginHost.ts:152-181` 的 `installPlugin(plugin, identity)` 走运行中安装，带熔断与卸载句柄。
3. 装配 → `pluginHost.ts:196-199` 调 `assemblePlugins`；`pluginApi.ts:148-156` 依次执行每个插件收集意向，再把同名槽 fan-out 成一个复合 hook（`pluginApi.ts:158-221`）。合成语义各不相同：`onRunStart`/`transformContext`/`prepareRequest` 按序 await 全跑；`beforeToolCall` 首个 `{block:true}` 胜且短路；`afterToolCall` 串成补丁管道；`onTurnEnd` 首个 `{stop:true}` 胜；`shouldStop` 首个通过 `validateShouldStopDecision` 的决定胜。无人注册的槽产出 `undefined`，loop 侧靠 `?.` 跳过。
4. 触发 → 主循环七个调用点，**7/7 都已接线**：`onRunStart` @ `toolLoopBootstrap.ts:54`；`transformContext` @ `modelTurnRequester.ts:153`；`prepareRequest` @ `modelTurnRequester.ts:159`；`beforeToolCall` @ `toolCallPluginHooks.ts:65`；`afterToolCall` @ `toolCallPluginHooks.ts:113`；`onTurnEnd` @ `toolLoopCycle.ts:98`；`shouldStop` @ `toolLoopCycle.ts:120`。全部拿 `base.pluginContext`（`toolLoopBootstrap.ts:95` 造的 `CoreCtx`）作第一参。
5. 执行/读写 → 插件只能经 `CoreCtx`（`coreCtx.ts:20-39`）动状态：`store`（会话）、`root`（跨会话）、`history`（事务日志，带上它 ctx 就结构性满足 `SlotWriteTarget`）、`isCurrent()`、`traceEvent()`。示例：`finishReasonPlugin.ts:90` 走 `appendItemToSession(ctx, item)` 记账写入；`migrationPlugin.ts:50-52` 先 `ctx.isCurrent()` 自查再写 `sessionsAtom`。
6. 结果去哪 → 变换型直接改 `draft.messages`（不写回 `itemsAtom`，`loopHooks.ts:20-23` 写明理由）；终止型返回决策，由 loop 消费：`toolLoopCycle.ts:100-117` 拿 `TurnEndStopDecision` 的 `runStatus/reason/traceEventName/traceAttrs` 一次落地，`:130-138` 处理 `ShouldStopDecision`。run 结束时 `runToolLoop.ts:176` / `toolLoopBootstrap.ts:151` 调 `pluginRun.dispose()` 收订阅与 disposer。

## 每部分负责什么 / 状态归谁 / 谁能调谁
| 部分 | 职责 | 持有的状态 | 谁可以调它 | 不许做 |
|---|---|---|---|---|
| `loopHooks.ts` | 定义 7 个槽的形状 + `TurnEnd`/`ShouldStop` 决策类型与运行时校验 | 无 | 插件、`pluginApi`、loop | 不接 store，不做 IO |
| `pluginApi.ts` | 注册面 + fan-out 装配；产出 `AssembledPlugins` | 装配期 buckets/tools/订阅意向（每 run 一份） | `pluginHost.activateRun` | 不碰任何全局 registry 单例（`:38-39`） |
| `pluginHost.ts` | 安装期工具所有权 + 每 run 生命周期 + 三种输入形状适配 | `plugins[]`、`activeRuns`、`dynamicInstallations` | `CoreInstance`（`coreInstance.ts:203`）、插件加载器 | 工具重名即整体拒绝、不留半装（`:123-135`） |
| 4 个插件本体 | 各自一个横切关注点 | 只有 loopGuard 有跨轮闭包计数（`loopGuardPlugin.ts:113-114`，per-run 隔离） | 只被 `assemblePlugins` 调 | 不 import `CoreInstance`；不发 loop 该发的 trace（`loopGuardPlugin.ts:40`） |
| `pluginContracts.ts` | 外部插件的**受限**投影 | 无 | `plugin.ts` 公开入口、`pluginToolGate` | 不投影 store/atom/CoreCtx（`:1`、`coreCtx.ts:25-26`） |
| `pluginCircuitBreaker.ts` | 动态插件连续 3 次 hook 失败即自动停用 | 每次 wrap 一份闭包计数（`:43-44`） | `pluginHost.installPlugin` | 只代理 `activate`，不管 `install`（`:35-36`） |
| `packages/agent-core/src/plugins/*` | 目录插件的 manifest/扫描/加载/工具闸门 | 无长期状态 | `apps/cli/src/plugins.ts:76`、`apps/web/src/plugins/*` | 不碰 IO，`importModule` 由宿主注入（`pluginLoader.ts:8-11`） |
| `packages/agent-react/*` | timeline renderer 的 per-root 注册表与 UI 插件安装面 | 每个 React root 一份 registry | React root | 拿不到 CoreInstance/atom/command（例包 README:16-18） |

## 形状（分支线：目录/文件形状 + 计数；必需 vs 可选）
- `runtime/core/plugins/` 成员 **13 个**（git 跟踪）= **6 实现 + 7 测试**。6 个实现里：
  - 精确主形状 **3/6** `{具名本体函数 + `export const xPlugin: AgentPlugin = (api) => api.hook(槽, 本体)` + colocated `*.test.ts`}` —— migration / finishReason / loopGuard。
  - 另一类 **2/6**：`defaultPlugins.ts`（登记表，不是插件）、`compactionProjectionCache.ts`（纯投影缓存，不是插件）。
  - 不合形状 **1/6**：`compactionPlugin.ts`（见「标准之外」）。
- 每个插件挂几个 hook：**各 1 个**（`migrationPlugin.ts:59` / `finishReasonPlugin.ts:107` / `loopGuardPlugin.ts:184` / `compactionPlugin.ts:480`）。7 个槽里**默认只有 2 个**有注册方（`onRunStart` 1 个、`onTurnEnd` 2 个），其余 5 个在默认装配下恒为 `undefined`。
- 插件输入形状 **3 种**（`pluginHost.ts:20` 的 `PluginInput`）：`CorePlugin{install?,activate?}`、旧 `AgentPlugin`（函数，`:85-97` 适配）、`PublicPlugin`（`definePlugin` 品牌，`:79-84` 适配）。
- 外部插件能触到的面**远小于**仓内：install 期 1 件事（`registerTool`，`pluginContracts.ts:79-81`），run 期 3 件事（`commands` / `observeRun` / `onAfterToolCall`，`:72-76`）——7 个槽里只映射到 `afterToolCall` 一个（`pluginHost.ts:65-73`），且回调返回值被丢弃、只能观察不能改结果。
- 必需：一个 `AgentPlugin` 导出 + 一次 `api.hook`。可选：本体函数拆出（3/4 都拆了）、per-run 闭包状态、私有扩展 draft 字段、colocated 测试（4/4 都有）。
